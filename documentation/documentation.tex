\chapter*{Rezumat}
\addcontentsline{toc}{chapter}{Rezumat}
\markboth{Rezumat}{Rezumat}

Prezenta lucrare de licență descrie proiectarea, implementarea și testarea unei aplicații mobile
cross-platform denumită \textbf{FocusQuest}, dezvoltată cu React Native și TypeScript.
Aplicația îmbină elemente de joc de rol (RPG) cu instrumente de productivitate, fiind
destinată oricui este interesat de productivitate, studiu și jocuri inteligente cu AI, mai
ales elevilor care urmează să susțină admiterea pentru intrarea la Universitatea Politehnica Timișoara.

Principalele contribuții ale lucrării sunt:
\begin{itemize}[leftmargin=1.5cm]
  \item Integrarea unui model de rețea neuronală convoluțională (\textit{ResNet-50 INT8}) rulat
    \textit{on-device} prin ONNX Runtime React Native, utilizat pentru clasificarea imaginilor
    în jurnalul digital al utilizatorului.
  \item Integrarea motorului de șah \textit{Maia Chess} — un model antrenat să imite stilul
    de joc uman la diverse niveluri Elo (1100–1500) — rulat complet local, fără conexiune la
    internet.
  \item Un sistem de economie virtuală bazat pe monede câștigate prin sesiuni de concentrare,
    jocuri și activități de învățare, utilizat pentru deblocarea conținutului de dificultate
    mai ridicată.
  \item Un modul de învățare structurat pe trei discipline matematice (algebră, analiză şi
    trigonometrie), cu probleme matematice şi soluții pas-cu-pas
    randate cu KaTeX.
  \item Persistența stării aplicației folosind AsyncStorage și un gestionar global de stare
    bazat pe React Context API cu \texttt{useReducer}.
  \item Un sistem de gamificare de tip RPG ce cuprinde experiență (XP) cu niveluri progresive,
    quest-uri zilnice cu resetare automată și efecte sonore retro sintetizate, proiectat
    pentru a susține motivația pe termen lung.
  \item Un modul de examen simulat (12 întrebări extrase aleatoriu, câte 4 din fiecare
    disciplină) și un set de puzzle-uri de șah de tip ``mat în $N$ mutări'' validate
    algoritmic cu \texttt{chess.js}, pentru consolidarea cunoștințelor și a gândirii tactice.
\end{itemize}

Aplicația a fost testată pe dispozitive Android și respectă arhitectura componentelor React
Native, cu o separare clară a logicii de afaceri față de stratul de prezentare.

\textbf{Cuvinte cheie:} React Native, TypeScript, ONNX Runtime, ResNet-50, Maia Chess,
gamificare, niveluri XP, examen simulat, puzzle-uri de șah, aplicație mobilă, productivitate,
algoritmi de backtracking, KaTeX.

\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}
\markboth{Abstract}{Abstract}

This bachelor thesis describes the design, implementation and testing of a cross-platform
mobile application called \textbf{FocusQuest}, built with React Native and TypeScript.
The application combines role-playing game (RPG) mechanics with productivity tools, aimed at
anyone interested in productivity, learning and intelligent games.

The main contributions are:
\begin{itemize}[leftmargin=1.5cm]
  \item Integration of a convolutional neural network (\textit{ResNet-50 INT8}) running
    \textit{on-device} via ONNX Runtime React Native, used to classify images in the user's
    digital journal.
  \item Integration of the \textit{Maia Chess} engine — a model trained to mimic human chess
    playing style at various Elo levels (1100–1500) — running fully locally, without an
    internet connection.
  \item A virtual economy system based on coins earned through focus sessions, games and
    learning activities, used to unlock higher-difficulty content.
  \item A learning module structured around three mathematical disciplines (algebra, analysis
    and trigonometry), with mathematical problems and step-by-step
    solutions rendered with KaTeX.
  \item Application state persistence using AsyncStorage and a global state manager based on
    the React Context API with \texttt{useReducer}.
  \item An RPG-style gamification system comprising experience points (XP) with progressive
    levels, auto-resetting daily quests and synthesized retro sound effects, designed to
    sustain long-term motivation.
  \item A mock-exam module (12 randomly drawn questions, four per subject) and a set of
    ``mate-in-$N$'' chess puzzles algorithmically validated with \texttt{chess.js}, for
    reinforcing knowledge and tactical thinking.
\end{itemize}

\textbf{Keywords:} React Native, TypeScript, ONNX Runtime, ResNet-50, Maia Chess,
gamification, XP levels, mock exam, chess puzzles, mobile application, productivity,
backtracking algorithms, KaTeX.

\chapter{Introducere}

\section{Motivație și context}

Accesul tinerilor la instrumente moderne de studiu s-a diversificat semnificativ în ultimul
deceniu. Telefoanele inteligente sunt omniprezente în rândul elevilor și studenților, iar
aplicațiile mobile dedicate productivității și educației reprezintă un segment în creștere
rapidă al pieței de software. Cu toate acestea, există o lipsă acută de aplicații care să
combine în mod integrat:
\begin{enumerate}
  \item Tehnici de productivitate validate din punct de vedere \textit{\c{s}tiin\c{t}ific} (ex. tehnica Pomodoro);
  \item Conținut de pregătire pentru examene specifice sistemului de învățământ românesc;
  \item Mecanisme de gamificare care să mențină motivația pe termen lung;
  \item Modele de inteligență artificială care să funcționeze \textit{offline}, pe dispozitiv.
\end{enumerate}

\textbf{FocusQuest} răspunde acestei nevoi prin crearea unui ecosistem mobil coerent în care
studiul și distracția coexistă. Aplicația este construită cu un design vizual retro-neon RPG,
conceput să fie atractiv pentru generația Z, obișnuită cu estetica jocurilor video indie.

\section{Obiectivele lucrării}

Obiectivele principale ale acestei lucrări de licență sunt:
\begin{itemize}
  \item Proiectarea și implementarea unei aplicații mobile React Native complete, cu navigare
    multi-ecran, gestionare globală a stării și persistență locală a datelor.
  \item Integrarea a două modele ONNX \textit{on-device}: ResNet-50 pentru clasificarea
    imaginilor și Maia Chess pentru jocul de șah cu inteligență artificială.
  \item Construirea unui sistem de gamificare funcțional cu monede, experiență (XP) și
    niveluri, quest-uri zilnice, realizări deblocabile, inventar și dificultăți progresive.
  \item Furnizarea unui modul educațional cu exerciții matematice structurate, complet
    cu răspunsuri multiple şi soluții detaliate randate cu KaTeX, precum și a unui mod de
    examen simulat și a unui set de puzzle-uri de șah tactice.
  \item Demonstrarea viabilității rulării modelelor de rețele neuronale direct pe dispozitive
    mobile cu resurse limitate.
\end{itemize}

\section{Structura lucrării}

Lucrarea este organizată în nouă capitole:
\begin{itemize}
  \item \textbf{Capitolul 2} prezintă stadiul actual al domeniului (State of the Art),

    FocusQuest.
  \item \textbf{Capitolul 3} descrie tehnologiile și instrumentele utilizate în dezvoltare.
  \item \textbf{Capitolul 4} prezintă arhitectura generală a aplicației.
  \item \textbf{Capitolul 5} detaliază sistemul de gestiune a stării și persistența datelor.
  \item \textbf{Capitolul 6} descrie modulele funcționale principale ale aplicației.
  \item \textbf{Capitolul 7} analizează integrarea modelelor de inteligență artificială.
  \item \textbf{Capitolul 8} prezintă testarea și evaluarea aplicației.
  \item \textbf{Capitolul 9} concluzionează lucrarea și propune direcții viitoare de
    dezvoltare.
\end{itemize}

\chapter{Stadiul actual al domeniului (State of the Art)}

\section{Aplicații de productivitate și concentrare}

\subsection{Forest – Stay Focused}

Forest~\cite{forest} este una dintre cele mai cunoscute aplicații de productivitate cu element de
gamificare. Utilizatorul plantează un copac virtual care crește cât timp nu folosește
telefonul; dacă iese din aplicație, copacul moare. Aplicația colaborează cu organizații
de plantare a copacilor reali, ceea ce adaugă o dimensiune de impact social.

\textbf{Comparație cu FocusQuest:} Forest se concentrează exclusiv pe tehnica Pomodoro
și nu integrează niciun conținut educațional, niciun joc inteligent și niciun model AI.
FocusQuest extinde conceptul de concentrare cu un ecosistem complet: sesiunile de focus
generează monede care permit accesul la jocuri și conținut educațional.

\subsection{Todoist și Notion}

Todoist și Notion sunt instrumente de gestionare a sarcinilor și note-taking, utilizate
frecvent de studenți pentru organizarea studiului. Deși extrem de versatile, aceste aplicații
nu oferă gamificare intrinsecă, nu integrează modele AI locale şi nu sunt orientate spre
practică structurată de exerciții matematice.

\subsection{Flora – Green Focus}

Flora urmează un model similar cu Forest, cu accent pe productivitate în grup și provocări
sociale. Nu include elemente RPG, nu are jocuri integrate și nu are funcționalitate offline
bazată pe AI.

\section{Aplicații de învățare și pregătire pentru examene}

\subsection{Khan Academy}

Khan Academy oferă un curriculum vast, inclusiv matematică avansată, cu exerciții
interactive și progres vizibil. Platforma este gratuită și bine structurată, dar:
\begin{itemize}
  \item Nu este orientată spre conținut specific admiterii la universitățile românești;
  \item Nu are elemente de gamificare RPG;
  \item Nu integrează jocuri sau un sistem de monede;
  \item Necesită conexiune la internet.
\end{itemize}

\subsection{Brilliant.org}

Brilliant.org oferă cursuri interactive de matematică și informatică cu un nivel ridicat de
interactivitate. Interfața este modernă și angajantă, dar platforma este orientată spre
gândire conceptuală, nu spre pregătirea pentru examinări de tip grilă specifice.

\subsection{Duolingo}

Duolingo~\cite{duolingo} este exemplul canonic de aplicație educațională cu gamificare: streak-uri zilnice,
monede virtuale, nivele și personaje animate. FocusQuest se inspiră din principiile de design
ale Duolingo (streak-uri, monede, recompense), adaptate contextului unui RPG și extins cu
funcționalități AI locale.

\textbf{Diferența cheie față de FocusQuest:} FocusQuest combină zona de practică de exerciții
cu zona de jocuri (șah AI, Sudoku) și cu zona de productivitate (timer focus, geolocation)
într-o singură aplicație cu o economie virtuală unificată.

\section{Aplicații de șah cu AI}

\subsection{Chess.com și Lichess}

Chess.com și Lichess~\cite{lichess} sunt platformele dominante de șah online. Ambele oferă oponenți AI
la multiple niveluri de dificultate. Lichess este open-source și oferă motorul Stockfish~\cite{stockfish},
unul dintre cei mai puternici motori de șah din lume.

\textbf{Diferența față de FocusQuest:} FocusQuest nu utilizează Stockfish (care joacă la
nivel de campion mondial). În schimb, integrează \textbf{Maia Chess}, un model antrenat să
joace \textit{uman}, comițând greșeli tipice ale jucătorilor la niveluri Elo între 1100 și 1500.
Aceasta face experiența mult mai potrivită pentru jucători începători și intermediari.
Mai mult, FocusQuest rulează modelul complet offline, fără server.

\subsection{Magnus Trainer}

Magnus Trainer este o aplicație de antrenament la șah creată de campionul mondial Magnus
Carlsen. Oferă lecții, puzzle-uri și jocuri contra AI. Aplicația este premium și nu
integrează module de studiu sau productivitate.

\section{Aplicații cu clasificare AI a imaginilor}

\subsection{Google Lens}

Google Lens oferă recunoaștere de imagini de înaltă calitate, rulând pe serverele Google.
Necesită conexiune la internet și nu poate fi integrată offline într-o aplicație mobilă.

\subsection{Microsoft Azure Custom Vision}

Serviciu cloud pentru clasificare de imagini custom. Necesită abonament și conexiune la
internet; nu este potrivit pentru scenarii complet offline.

\textbf{Diferența față de FocusQuest:} FocusQuest rulează ResNet-50 INT8 direct pe
dispozitivul utilizatorului prin ONNX Runtime, fără niciun server extern, asigurând
confidențialitatea datelor și funcționalitate offline completă.

\section{Aplicații RPG educaționale}

\subsection{Habitica}

Habitica~\cite{habitica} transformă gestionarea obiceiurilor și sarcinilor zilnice într-un RPG: utilizatorul
are un personaj, câștigă experiență și obiecte, luptă cu monștri în grupuri. Este cea mai
apropiată aplicație conceptual de FocusQuest, dar:
\begin{itemize}
  \item Nu integrează modele AI locale;
  \item Nu oferă jocuri inteligente (șah, Sudoku);
  \item Nu are conținut educațional structurat cu exerciții specifice;
  \item Nu are un timer de concentrare dedicat cu animații de personaj.
\end{itemize}

\subsection{ClassDojo}

ClassDojo este orientat spre sala de clasă și gestionat de profesori, nu de elevi în mod
autonom. Nu are elemente de jocuri inteligente sau AI.

\chapter{Tehnologii și instrumente utilizate}

\section{React Native}

React Native~\cite{reactnative} este un framework open-source dezvoltat de Meta (Facebook) care permite
crearea de aplicații mobile native pentru iOS și Android folosind JavaScript și TypeScript.
Spre deosebire de abordările hibride (ex. Ionic, Cordova), React Native compilează
componentele la UI nativ al platformei, nu la WebView, rezultând o performanță apropiată
de aplicațiile native.

Versiunea utilizată în proiect este \textbf{React Native 0.82.0} împreună cu
\textbf{React 19.1.1}.

Avantajele care au determinat alegerea React Native:
\begin{itemize}
  \item Baza de cod partajată pentru iOS și Android;
  \item Ecosistem bogat de biblioteci (navigare, stocare, imagini, sunet);
  \item Suport nativ pentru TypeScript;
  \item Compatibilitate cu ONNX Runtime prin pachetul \texttt{onnxruntime-react-native}.
\end{itemize}

\section{TypeScript}

TypeScript~\cite{typescript} este un superset al JavaScript care adaugă tipizare statică. Întregul proiect
este scris în TypeScript, ceea ce oferă:
\begin{itemize}
  \item Detectarea timpurie a erorilor la compilare;
  \item Autocompletare și refactorizare mai bune în IDE;
  \item Documentare implicită a structurilor de date complexe (ex. \texttt{GameState}).
\end{itemize}

\section{React Navigation}

Navigarea în aplicație este gestionată de biblioteca \textbf{React Navigation 7.x}~\cite{reactnavigation},
utilizând două tipuri de navigatori:
\begin{itemize}
  \item \texttt{createBottomTabNavigator} — pentru cele cinci ecrane principale
    (Focus, Arcade, Learning, Journal, Profile);
  \item \texttt{createNativeStackNavigator} — pentru ecranele secundare
    (Achievements, Statistics, Inventory, ExerciseList, ExerciseDetail).
\end{itemize}

\section{AsyncStorage}

\textbf{@react-native-async-storage/async-storage}~\cite{asyncstorage} (versiunea 2.1.0) este biblioteca
de stocare cheie-valoare persistentă utilizată pentru salvarea stării aplicației între
sesiuni. Datele sunt serializate în format JSON și stocate local pe dispozitiv sub cheia
\texttt{retro-arcade-study-state-v1}.

\section{ONNX Runtime React Native}

\textbf{onnxruntime-react-native}~\cite{onnxruntime} (versiunea 1.20.0) este un pachet care expune
ONNX Runtime~\cite{onnxformat} — un motor de inferență pentru modele de machine learning în format ONNX
— aplicațiilor React Native. Permite rularea modelelor complet local, fără server.

Funcționalitățile utilizate:
\begin{itemize}
  \item \texttt{InferenceSession.create()} — încărcarea modelului ONNX din fișier;
  \item \texttt{session.run(feeds)} — executarea inferenței cu un dicționar de tensori
    de intrare;
  \item \texttt{Tensor} — crearea tensorilor de tip \texttt{float32} și \texttt{int64}.
\end{itemize}

\section{chess.js}

\textbf{chess.js}~\cite{chessjs} (versiunea 1.0.0) este o bibliotecă JavaScript de logică a jocului
de șah. Oferă:
\begin{itemize}

\section{Sistemul de acțiuni (Reducer)}

Reducer-ul gestionează peste 24 de tipuri de acțiuni, dintre care cele mai importante sunt:

\begin{description}
  \item[\texttt{COMPLETE\_SESSION}] Finalizarea unei sesiuni de focus. Calculează monedele
    câștigate (\textit{baseReward} + \textit{streakBonus}), actualizează streak-ul și
    salvează sesiunea cu datele de geolocation.
  \item[\texttt{ADD\_FLASHCARD / UPDATE\_FLASHCARD / DELETE\_FLASHCARD}] Gestionarea
    intrărilor din jurnal.
  \item[\texttt{COMPLETE\_CHESS\_GAME / COMPLETE\_MAIA\_CHESS\_GAME}] Înregistrarea
    rezultatelor partidelor de șah cu actualizarea statisticilor și acordarea recompenselor.
  \item[\texttt{COMPLETE\_SUDOKU\_GAME}] Finalizarea unui puzzle Sudoku cu acordarea
    monedelor.
  \item[\texttt{UNLOCK\_MAIA\_DIFFICULTY / UNLOCK\_SUDOKU\_DIFFICULTY}] Deblocarea
    nivelelor de dificultate mai ridicate contra cost de monede.
  \item[\texttt{UNLOCK\_ACHIEVEMENT}] Deblocarea unei realizări.
  \item[\texttt{MARK\_EXERCISE\_SOLVED}] Marcarea unui exercițiu ca rezolvat.
  \item[\texttt{COMPLETE\_QUIZ}] Finalizarea unui examen simulat: acordă monede și XP,
    actualizează statisticile și adaugă în progresul de învățare exercițiile rezolvate corect.
  \item[\texttt{COMPLETE\_PUZZLE}] Înregistrarea rezolvării unui puzzle de șah (recompensă
    acordată o singură dată per puzzle).
  \item[\texttt{CLAIM\_QUEST / REFRESH\_DAILY}] Revendicarea unui quest zilnic finalizat,
    respectiv resetarea contoarelor la schimbarea zilei calendaristice.
  \item[\texttt{HYDRATE}] Restaurarea stării din AsyncStorage la pornirea aplicației.
\end{description}

Fiecare acțiune care acordă recompense (sesiuni de focus, victorii la jocuri, exerciții,
examene, puzzle-uri) incrementează simultan câmpul \texttt{xp}, iar acțiunile relevante
actualizează contoarele zilnice utilizate de quest-uri.

\section{Formula de calcul a monedelor din sesiunile de focus}

Monedele câștigate per sesiune de focus sunt calculate conform Ecuației~\ref{eq:coins}:

\begin{equation}
  \text{coinsEarned} = \max(3,\; \lfloor \text{durationMinutes} \times 1{,}5 \rfloor)
  + \left\lfloor \frac{\text{streak}}{3} \right\rfloor
  \label{eq:coins}
\end{equation}

unde \textit{durationMinutes} este durata sesiunii în minute, iar \textit{streak} este
numărul curent de zile consecutive cu cel puțin o sesiune completată.

\section{Sistemul de streak}

Streak-ul este calculat pe baza datei calendaristice (nu a orei):
\begin{itemize}
  \item Dacă ultima sesiune a fost azi: streak rămâne nemodificat;
  \item Dacă ultima sesiune a fost ieri: streak crește cu 1;
  \item Altfel: streak se resetează la 1.
\end{itemize}

\section{Sistemul de experiență (XP) și niveluri}
\label{sec:xp}

Pe lângă economia de monede (resursă consumabilă pentru deblocări), aplicația implementează
un sistem de \textbf{experiență (XP)} cumulativă, ireversibilă, care determină \textbf{nivelul}
jucătorului — un indicator de progres pe termen lung specific jocurilor de rol. Puncte de
experiență sunt acordate pentru aproape fiecare activitate productivă: minute de concentrare,
exerciții rezolvate, victorii la șah/Sudoku, examene simulate, puzzle-uri și revendicarea
quest-urilor zilnice.

XP-ul necesar pentru a avansa de la nivelul $L$ la nivelul $L+1$ crește liniar
($\text{XP\_STEP} \times L$, cu $\text{XP\_STEP} = 100$), astfel încât XP-ul cumulativ
necesar pentru a \emph{atinge} nivelul $L$ este dat de Ecuația~\ref{eq:xp}:

\begin{equation}
  \text{totalXP}(L) = \text{XP\_STEP} \cdot \frac{(L-1)\,L}{2}
  \label{eq:xp}
\end{equation}

Nivelul curent se obține prin inversarea acestei relații (Ecuația~\ref{eq:level}):

\begin{equation}
  L(\text{xp}) = \left\lfloor \frac{1 + \sqrt{1 + 8\,\text{xp}/\text{XP\_STEP}}}{2} \right\rfloor
  \label{eq:level}
\end{equation}

Funcțiile pure de conversie sunt izolate în modulul \texttt{src/constants/leveling.ts}, fiind
reutilizate atât de interfață (bara de progres \texttt{LevelBar}), cât și de sistemul de
realizări. La trecerea într-un nivel superior, aplicația oferă un \textit{feedback} dedicat
(efect sonor de tip fanfară și vibrație), detectat printr-un \texttt{useEffect} care compară
nivelul curent cu cel anterior.

\section{Persistența cu AsyncStorage}

La fiecare modificare a stării, datele sunt serializate JSON și salvate asincron:

\begin{lstlisting}[language=Java, caption={Salvarea și restaurarea stării}]
// Salvare
useEffect(() => {
  if (isHydrated) {
    AsyncStorage.setItem(STORAGE_KEY, JSON.stringify(state));
  }
}, [state, isHydrated]);

// Restaurare la pornire
useEffect(() => {
  AsyncStorage.getItem(STORAGE_KEY).then(raw => {
    if (raw) {
      const parsed = JSON.parse(raw) as GameState;
      dispatch({ type: 'HYDRATE', payload: parsed });
    }
    setIsHydrated(true);
  });
}, []);
\end{lstlisting}

Cheia de stocare este versionată (\texttt{retro-arcade-study-state-v1}) pentru a permite
migrări viitoare de schemă fără a pierde datele existente.

Restaurarea stării (acțiunea \texttt{HYDRATE}) nu este o simplă atribuire a obiectului
deserializat, ci o operație defensivă de îmbinare. Starea salvată este combinată cu
\texttt{initialState} folosit ca bază (\textit{baseline}), astfel încât orice câmp nou,
introdus într-o versiune mai recentă a aplicației și absent din datele salvate anterior, să
primească automat valoarea sa implicită. În plus, reducer-ul revalidează sub-structurile
critice: obiectele de inventar sunt re-rezolvate față de catalogul curent (pentru a prelua
eventualele modificări de denumire sau imagine), iar nivelurile de dificultate deblocate la
șah sunt rederivate din numărul de victorii înregistrate. Acest mecanism protejează
aplicația împotriva datelor parțial corupte sau învechite și asigură că interfața primește
întotdeauna o stare completă și coerentă, indiferent de versiunea în care au fost salvate
inițial datele.

\section{Context API și hook-ul \texttt{useGame}}

Starea și funcțiile de modificare sunt expuse prin \texttt{GameContext} și consumate prin
hook-ul \texttt{useGame()}. Această abordare evită prop drilling și centralizează toată
logica de business.

Alegerea combinației \texttt{Context API + useReducer} în locul unei biblioteci externe de
gestiune a stării (precum Redux sau Zustand) a fost una deliberată: aplicația dispune de o
singură sursă de adevăr (\textit{single source of truth}), iar volumul de logică nu
justifică dependențele și boilerplate-ul suplimentar ale unui store extern. Funcțiile de
acțiune expuse prin context (de exemplu \texttt{completeSession}, \texttt{finishChessMatch},
\texttt{markExerciseSolved}) sunt memoizate, astfel încât referințele lor să rămână stabile
între re-randări și să nu provoace re-randarea inutilă a componentelor consumatoare.
O parte din logica de rezolvare — calculul recompenselor, extragerea aleatorie a obiectelor
de inventar și verificarea pragurilor de deblocare — este încapsulată direct în aceste
funcții, care returnează către interfață obiecte de rezultat (\textit{resolution objects})
folosite ulterior pentru afișarea ferestrelor modale de confirmare. Astfel, componentele de
prezentare rămân subțiri, iar regulile de joc sunt concentrate într-un singur loc, ușor de
testat și de întreținut.

\begin{enumerate}

  \item Puzzle-uri preîncărcate din constantele \texttt{EASY\_PUZZLES},

  \item Un algoritm de backtracking pentru validarea și rezolvarea puzzle-urilor.

\subsubsection{Algoritmul de backtracking}

Puzzle-urile Sudoku sunt rezolvate prin backtracking recursiv. Algoritmul:
\begin{enumerate}
  \item Caută prima celulă goală (\textit{findEmpty});
  \item Încearcă numerele de la 1 la 9;
  \item Verifică validitatea plasării față de rând, coloană și sub-carou $3\times3$;
  \item Dacă nu există număr valid, revine la celula anterioară.
\end{enumerate}

\begin{lstlisting}[language=Java, caption={Algoritmul de backtracking Sudoku}]
const solveSudoku = (grid: (number | null)[][]): boolean => {
  const findEmpty = (): [number, number] | null => {
    for (let row = 0; row < 9; row++)
      for (let col = 0; col < 9; col++)
        if (grid[row][col] === null) return [row, col];
    return null;
  };

  const isValid = (num: number, row: number, col: number): boolean => {
    for (let x = 0; x < 9; x++)
      if (grid[row][x] === num || grid[x][col] === num) return false;
    const sr = Math.floor(row / 3) * 3;
    const sc = Math.floor(col / 3) * 3;
    for (let i = 0; i < 3; i++)
      for (let j = 0; j < 3; j++)
        if (grid[sr + i][sc + j] === num) return false;
    return true;
  };

  const empty = findEmpty();
  if (!empty) return true; // Rezolvat!
  const [r, c] = empty;
  for (let num = 1; num <= 9; num++) {
    if (isValid(num, r, c)) {
      grid[r][c] = num;
      if (solveSudoku(grid)) return true;
      grid[r][c] = null;
    }
  }
  return false;
};
\end{lstlisting}

\subsection{Mecanismul de deblocare automată}

Spre deosebire de sistemele care necesită o verificare declanșată manual, deblocarea
realizărilor în FocusQuest este complet automată. Un efect lateral (\texttt{useEffect})
prevăzut cu un mecanism de \textit{debounce} de 500\,ms monitorizează modificările stării

concentrare, care actualizează simultan monedele, streak-ul, totalul de minute și istoricul
sesiunilor. În momentul în care numărul de realizări deblocate crește, aplicația oferă un
feedback haptic prin vibrație (\texttt{Vibration.vibrate}), confirmând tactil progresul
utilizatorului fără a întrerupe fluxul curent al interfeței. Această abordare reactivă
garantează că o realizare este acordată imediat ce condiția sa este îndeplinită, indiferent
de ecranul pe care se află utilizatorul în acel moment.

\subsection{Randarea formulelor matematice (MathRenderer)}

Componenta \texttt{MathRenderer} este construită pe un \texttt{WebView} care injectează
biblioteca KaTeX pentru randarea formulelor LaTeX. Caracteristici tehnice:
\begin{itemize}
  \item Suportă atât formule inline (\texttt{\$...\$}) cât și formule bloc (\texttt{\$\$...\$\$});
  \item Definește macrouri pentru notațiile românești: \texttt{\textbackslash tg},
    \texttt{\textbackslash ctg}, \texttt{\textbackslash arctg}, \texttt{\textbackslash arcctg};
  \item Înălțimea WebView-ului se ajustează dinamic prin mesaje
    \texttt{postMessage} de la KaTeX;
  \item Biblioteca KaTeX este încărcată din CDN-ul public \texttt{jsdelivr}, ceea ce face ca
    randarea formulelor să fie singura componentă a aplicației dependentă de conectivitate.
\end{itemize}

\subsubsection{Singura dependență de conectivitate}
\label{sec:online-dependency}

Spre deosebire de restul aplicației, componenta \texttt{MathRenderer} încarcă biblioteca
KaTeX în mod dinamic dintr-o rețea de distribuție de conținut (CDN), motiv pentru care
randarea formulelor matematice din modulul de învățare reprezintă \textbf{singura
funcționalitate care necesită o conexiune activă la internet}. Această abordare a fost
preferată în detrimentul împachetării locale a bibliotecii (\textit{bundling}) pentru a
păstra dimensiunea pachetului aplicației redusă și pentru a beneficia de versiunea
optimizată și cache-uită a CDN-ului. O direcție imediată de îmbunătățire (Capitolul~9)
este împachetarea fișierelor KaTeX direct în resursele aplicației, ceea ce ar elimina
și această ultimă dependență, transformând FocusQuest într-o aplicație complet
funcțională \textit{offline}. Restul funcționalităților — inferența ONNX (ResNet-50 și
Maia Chess), persistența datelor, jocurile, timer-ul de concentrare și sistemul de
gamificare — operează în întregime local, fără niciun apel de rețea. Singura excepție
parțială o constituie geolocalizarea: obținerea coordonatelor GPS este locală, însă
transformarea acestora în denumirea localității (\textit{reverse geocoding}) folosește
serviciul Nominatim; în absența conexiunii, această etapă eșuează elegant, sesiunea
fiind salvată cu coordonatele numerice brute, fără a bloca funcționalitatea.

\subsection{Fluxul de rezolvare a exercițiilor}

\begin{enumerate}
  \item Utilizatorul selectează o disciplină și un exercițiu;
  \item Problema și cele 4–5 variante de răspuns sunt afișate cu MathRenderer;

\section{Modelul ResNet-50 pentru clasificarea imaginilor}

\subsection{Descriere model}

\textbf{ResNet-50}~\cite{resnet} (Residual Network cu 50 de straturi) este o arhitectură CNN
(Convolutional Neural Network) dezvoltată de Microsoft Research, câștigătoare a
competiției ImageNet~\cite{imageNet} Large Scale Visual Recognition Challenge (ILSVRC) 2015.

Versiunea utilizată este \textbf{ResNet-50-v1-7 quantizat INT8} din ONNX Model Zoo~\cite{onnxmodelzoo},
cu dimensiune redusă față de versiunea float32 originală. Modelul clasifică imaginile
în \textbf{1000 de clase ImageNet}.

Parametrii modelului:
\begin{itemize}
  \item Dimensiune intrare: $1 \times 3 \times 224 \times 224$ (batch, canale RGB, înălțime, lățime);
  \item Dimensiune ieșire: $1 \times 1000$ (logit-uri pentru 1000 de clase);
  \item Normalizare intrare: medie $\mu = [0.485, 0.456, 0.406]$, deviație standard
    $\sigma = [0.229, 0.224, 0.225]$ (standardul ImageNet).
\end{itemize}

\subsection{Hook-ul \texttt{useOnnxClassifier}}

Hook-ul \texttt{useOnnxClassifier} gestionează ciclul de viață al sesiunii ONNX:
\begin{enumerate}
  \item \textbf{Încărcare model} — asincron la montarea componentei;
  \item \textbf{Preprocesare imagine} — decodificare JPEG, redimensionare la $224\times224$,
    normalizare și construirea tensorului;
  \item \textbf{Inferență} — \texttt{session.run(feeds)};
  \item \textbf{Postprocesare} — aplicarea \textit{softmax} și selectarea top-K clase.
\end{enumerate}

\subsection{Preprocesarea imaginilor}

Preprocesarea implementată reproduce exact pipeline-ul standard ImageNet:

\begin{lstlisting}[language=Java, caption={Preprocesarea imaginii pentru ResNet-50}]
function preprocessImage(base64: string): Tensor {
  const buffer = Buffer.from(base64, 'base64');
  const decoded = decodeJpeg(buffer, { useTArray: true });
  const resized = resizeToSquare(decoded, 224);
  const tensorData = new Float32Array(3 * 224 * 224);

  // Normalizare ImageNet
  const mean = [0.485, 0.456, 0.406];
  const std  = [0.229, 0.224, 0.225];

  for (let y = 0; y < 224; y++) {
    for (let x = 0; x < 224; x++) {
      const idx = y * 224 + x;
      const si  = idx * 4; // sursa RGBA
      // Format planar: R, G, B in blocuri separate
      tensorData[idx]               = (resized.data[si]   / 255 - mean[0]) / std[0];
      tensorData[idx + 224 * 224]   = (resized.data[si+1] / 255 - mean[1]) / std[1];
      tensorData[idx + 224 * 224*2] = (resized.data[si+2] / 255 - mean[2]) / std[2];
    }
  }
  return new Tensor('float32', tensorData, [1, 3, 224, 224]);
}
\end{lstlisting}

\subsection{Funcția softmax și selectarea predicțiilor}

Logit-urile de ieșire ale modelului sunt transformate în probabilități prin funcția
softmax numerică stabilă (Ecuația~\ref{eq:softmax}):
\begin{equation}
  \text{softmax}(z_i) = \frac{e^{z_i - \max(\mathbf{z})}}{\sum_{j=1}^{K} e^{z_j - \max(\mathbf{z})}}
  \label{eq:softmax}
\end{equation}

Predicțiile sunt sortate descendent după probabilitate și returnate primele K (implicit $K=3$).
Etichetele textuale corespunzătoare indicilor de clasă sunt extrase din fișierul
\texttt{classes.json}, care conține denumirile celor 1000 de clase ImageNet.

\subsection{Integrarea în fluxul jurnalului}

În contextul modulului de jurnal, rezultatul clasificării nu este impus utilizatorului, ci
oferit ca \textbf{sugestie}. La selectarea unei imagini din galerie sau de la cameră,
imaginea este convertită în Base64, decodificată, preprocesată și transmisă modelului, iar
primele trei etichete cu probabilitatea cea mai mare sunt propuse ca posibil titlu al
intrării de jurnal. Utilizatorul poate accepta una dintre sugestii printr-o singură atingere
sau poate ignora complet propunerile și introduce manual un titlu. Această proiectare
păstrează controlul deplin al utilizatorului asupra conținutului, folosind modelul AI ca
instrument de asistență, nu ca mecanism de etichetare automată obligatorie. În eventualitatea
unei erori de inferență sau a unei imagini ce nu poate fi decodificată, fluxul de creare a
intrării continuă neîntrerupt, fără sugestii, evitând blocarea interfeței.

\section{Modelul Maia Chess pentru jocul de șah cu AI}

\subsection{Descriere model Maia Chess}

\textbf{Maia Chess}~\cite{maiacChess} este un proiect de cercetare open-source al Universității Cornell
(Reid McIlroy-Young et al., 2020) care antrenează rețele neuronale să joace șah imitând
stilul uman la diverse niveluri Elo. Codul sursă și modelele sunt disponibile pe
GitHub~\cite{maiaGitHub}. Spre deosebire de motoarele tradiționale (Stockfish,
Leela Chess Zero) care maximizează forța de joc, Maia optimizează \textit{acordul cu
mutările umane} la un Elo dat.

Modelul utilizat este \textbf{maia\_rapid.onnx} — un model unic (rapid model) care
acoperă intervalul Elo 1100–1900. Nivelul de joc este controlat prin doi parametri
de intrare suplimentari: \texttt{elo\_self} și \texttt{elo\_oppo}.

\subsection{Arhitectura modelului}

Modelul Maia are \textbf{3 intrări}:
\begin{enumerate}
  \item \texttt{boards} — tensor de tip \texttt{float32} cu forma $[1, 18, 8, 8]$
    reprezentând starea tablei;
  \item \texttt{elo\_self} — tensor de tip \texttt{int64} cu forma $[1]$, categoria Elo
    a modelului (0–10);
  \item \texttt{elo\_oppo} — tensor de tip \texttt{int64} cu forma $[1]$, categoria Elo
    a adversarului.
\end{enumerate}

Și o \textbf{ieșire}:
\begin{itemize}
  \item \texttt{logits\_maia} — tensor de tip \texttt{float32} cu forma $[1, 1880]$,
    reprezentând scorul pentru fiecare mutare din dicționarul oficial de 1880 mutări
    UCI al proiectului Maia.
\end{itemize}

\subsection{Codificarea stării tablei (18 canale)}

\subsection{Tehnica de oglindire FEN}

O problemă critică în implementare este că modelul Maia a fost antrenat întotdeauna
din perspectiva albului. Prin urmare, când negrul este la mutare, tabla trebuie
\textbf{oglindită} înainte de a fi transmisă modelului:

\begin{enumerate}
  \item Rândurile FEN sunt inversate (rândul 8 devine rândul 1 și invers);
  \item Culorile pieselor sunt interschimbate (litere mari $\leftrightarrow$ litere mici);
  \item Rândul la mutare este interschimbat (w $\leftrightarrow$ b);
  \item Drepturile de rocadă sunt oglindite (K $\leftrightarrow$ k, Q $\leftrightarrow$ q);
  \item Câmpul en passant este oglindit (rândul $r \rightarrow 9-r$).
\end{enumerate}

Dacă board-ul a fost oglindit, mutarea selectată de model trebuie și ea oglindită
înapoi la coordonatele originale înainte de a fi executată.

\subsection{Selectarea mutării optime}

Algoritmul de selecție:
\begin{enumerate}
  \item Se generează lista tuturor mutărilor legale cu \texttt{chess.js};
  \item Fiecare mutare legală este convertită în format UCI (cu oglindire dacă e
    necesar) și căutată în \texttt{all\_moves.json} (1880 intrări);
  \item Logit-ul corespunzător este extras din ieșirea modelului;
  \item Se aplică softmax \textbf{doar} pe mutările legale (nu pe toți cei 1880
    candidați) pentru a preveni dispersia probabilistică;
  \item Se returnează mutarea cu probabilitatea maximă.
\end{enumerate}

\begin{lstlisting}[language=Java, caption={Selecția mutării optime Maia}]
const logits = moveScores.map(ms => ms.logit);
const probs  = softmax(logits); // Softmax DOAR pe mutarile legale!

const movesWithProbs = moveScores.map((ms, i) => ({
  ...ms, prob: probs[i]
}));
movesWithProbs.sort((a, b) => b.prob - a.prob);
return movesWithProbs[0].move; // Mutarea cu probabilitate maxima
\end{lstlisting}

\subsection{Pregătirea și validarea offline a puzzle-urilor}

Fișierele sursă conțin, pentru fiecare puzzle, o descriere, poziția în format FEN și soluția
în notație algebrică standard (SAN). Un script offline procesează aceste fișiere și produce
un fișier JSON compact (aproximativ 39\,KB pentru 70 de puzzle-uri) inclus în aplicație.
Pentru fiecare candidat, scriptul:
\begin{enumerate}
  \item normalizează câmpul FEN (numărul mutării este corectat la o valoare validă);
  \item rejoacă întreaga soluție cu \texttt{chess.js}, convertind fiecare mutare în format
    UCI;
  \item verifică faptul că secvența se termină efectiv în \textbf{șah-mat} și că adâncimea
    coincide cu cea declarată (mat în $N$);
  \item elimină puzzle-urile cu sub-promovări (promovare în altă piesă decât regina), pe care
    interfața curentă nu le poate exprima.
\end{enumerate}
Astfel, fiecare puzzle livrat este garantat \textbf{corect și solvabil}, validarea fiind
făcută complet \textit{offline}, fără un motor de șah extern.

până la mat, actualizând indicatorul ``mat în $N$''. O mutare legală dar greșită este
respinsă (cu \textit{feedback} sonor) și permite reîncercarea; o mutare care dă \emph{direct}
mat este de asemenea acceptată. Tabla se orientează automat după culoarea aflată la mutare,

\section{Strategia de testare}

Aplicația a fost testată la multiple niveluri:
\begin{enumerate}
  \item \textbf{Testare unitară} — un test de bază de randare a componentei rădăcină,
    scris cu Jest și React Test Renderer;
  \item \textbf{Testare manuală funcțională} — verificarea tuturor fluxurilor utilizator
    pe dispozitive Android fizice;
  \item \textbf{Verificări de integritate în cod} — validări explicite la rulare (ex.
    numărul de mutări din dicționarul Maia, starea modelelor ONNX).
\end{enumerate}

\section{Testare unitară}

Proiectul include teste unitare de bază în directorul \texttt{\_\_tests\_\_/App.test.tsx}
folosind Jest (\texttt{@types/jest 29.5.13}) și \texttt{react-test-renderer}. Configurația
Jest este definită în \texttt{jest.config.js} cu preset-ul
\texttt{react-native}.

\section{Testarea inferenței ONNX}

Ambele modele ONNX sunt încărcate asincron la montarea componentei corespunzătoare,
prin \texttt{InferenceSession.create()}. Indicatorii vizuali de stare
(\texttt{isModelLoading}, \texttt{isModelReady}, \texttt{modelsError}) sunt expuși
prin hook-urile \texttt{useOnnxClassifier} și \texttt{useMaiaChessEngine}, permițând
UI-ului să afișeze un spinner de încărcare și să dezactiveze interacțiunile cât timp
modelul nu este pregătit.

O verificare de integritate explicită este prezentă în codul sursă pentru modelul Maia:
dacă fișierul \texttt{all\_moves.json} nu conține exact 1880 de intrări (numărul oficial
din specificația Maia), se emite un mesaj de eroare critic în consolă. Aceasta asigură
că dicționarul de mutări utilizat este cel corect din repository-ul oficial Maia.

\section{Comportamentul hook-ului de geolocalizare}

Hook-ul \texttt{useGeolocation} (\texttt{src/hooks/useGeolocation.ts}) implementează
obținerea locației în mai mulți pași, cu un mecanism de rezervă explicit:

\begin{enumerate}
  \item \textbf{Solicitare permisiune} \textemdash{} pe Android se afișează un
    dialog de sistem cu titlul \textit{``Location Permission''} care explică scopul
    utilizării GPS-ului; pe iOS se apelează \texttt{Geolocation.requestAuthorization()};
  \item \textbf{Obținere coordonate GPS} \textemdash{} se apelează
    \texttt{Geolocation.getCurrentPosition()} cu parametrii:
    \texttt{enableHighAccuracy: false}, \texttt{timeout: 15000 ms},
    \texttt{maximumAge: 10000 ms};
  \item \textbf{Reverse geocoding Nominatim} \textemdash{} coordonatele sunt
    trimise la \texttt{nominatim.openstreetmap.org/reverse}; din câmpul
    \texttt{address} al răspunsului JSON se extrage denumirea localității prin
    ierarhia: \texttt{city} $\rightarrow$ \texttt{town} $\rightarrow$
    \texttt{village} $\rightarrow$ \texttt{county};
  \item \textbf{Rezervă la eșec} \textemdash{} un bloc \texttt{catch} explicit
    salvează locația cu doar latitudinea și longitudinea, fără denumire,
    asigurând că funcționalitatea nu se blochează în absența conectivității.
\end{enumerate}

Permisiunea \texttt{ACCESS\_FINE\_LOCATION} este solicitată la montarea ecranului
principal (\texttt{HomeScreen}). Sesiunile afișează fie denumirea localității (dacă
geocodarea a reușit), fie coordonatele numerice în formatul
\texttt{Lat: X.XXXX, Lon: Y.YYYY}.

\section{Mecanismul de persistență a datelor}

Persistența cu AsyncStorage este proiectată să fie robustă prin două
mecanisme complementare vizibile în codul sursă:
\begin{itemize}
  \item \textbf{Scriere la fiecare modificare de stare} \textemdash{} un \texttt{useEffect}
    care depend de \texttt{state} apelează asincron \texttt{AsyncStorage.setItem}
    la fiecare acțiune de reducer;
  \item \textbf{Versioning} \textemdash{} cheia de stocare \texttt{retro-arcade-study-state-v1}
    este versionată, permițând migrări viitoare de schemă fără pierderea datelor
    existente. La restaurare (acțiunea \texttt{HYDRATE}), starea salvată este
    îmbinată cu \texttt{initialState} ca baseline, protejând împotriva câmpurilor
    lipsă apărute în versiuni mai noi ale aplicației.
\end{itemize}

\section{Testarea jocului de șah Maia}

Corectitudinea integrării Maia Chess a fost validată prin:
\begin{itemize}
  \item Verificarea că toate mutările executate de AI sunt mutări legale conform
    \texttt{chess.js};
  \item Verificarea tehnicii de oglindire FEN prin testarea pozițiilor specifice cu
    negrul la mutare;
  \item Verificarea că numărul de intrări în \texttt{all\_moves.json} este exact 1880
    (conform specificației Maia) — validare prezentă explicit în codul sursă la
    inițializarea modulului.
\end{itemize}

\section{Validarea offline a datelor de joc}

O parte din conținutul aplicației este validat \textbf{algoritmic, în avans}, în loc să fie
verificat manual, ceea ce crește încrederea în corectitudine:
\begin{itemize}
  \item \textbf{Puzzle-urile de șah} — fiecare poziție și soluție din colecția importată este
    rejucată cu \texttt{chess.js}, iar puzzle-ul este păstrat doar dacă secvența se termină în
    șah-mat la adâncimea declarată (Secțiunea~\ref{sec:puzzles}); puzzle-urile invalide sau cu
    sub-promovări sunt eliminate automat.
  \item \textbf{Cartea de deschideri de alb} — pentru fiecare deschidere, legalitatea celei
    de-a doua mutări a fost verificată împotriva unui set variat de răspunsuri ale negrului,
    garantând că AI-ul nu ajunge niciodată într-o mutare ilegală în deschidere.
  \item \textbf{Conținutul de învățare} — la importul exercițiilor au fost verificate
    integritatea câmpurilor, potrivirea răspunsului corect cu una dintre variante și unicitatea
    identificatorilor.
\end{itemize}
Aceste verificări sunt rulate la pregătirea datelor (\textit{build-time}), astfel încât
aplicația livrată conține doar conținut validat.

\chapter{Concluzii și direcții viitoare}

\section{Concluzii}

Prezenta lucrare a descris proiectarea și implementarea completă a aplicației mobile
\textbf{FocusQuest}, demonstrând viabilitatea unui produs software complex care combină
multiple domenii: productivitate, gamificare, educație și inteligență artificială
\textit{on-device}.

Principalele realizări tehnice ale proiectului sunt:

\begin{enumerate}
  \item \textbf{Integrarea reușită a ONNX Runtime în React Native} — ambele modele
    (ResNet-50 și Maia Chess) funcționează complet offline pe dispozitive Android,
    cu timpi de răspuns acceptabili pentru interacțiunea utilizatorului.

  \item \textbf{Implementarea corectă a motorului Maia Chess} — inclusiv rezolvarea
    problemelor critice de oglindire FEN, codificarea celor 18 canale de intrare,
    maparea Elo la categorii și selecția mutărilor prin softmax pe mutările legale.

  \item \textbf{Un sistem de gamificare complet și coerent} — cu economie virtuală
    (monede), experiență (XP) și niveluri progresive, quest-uri zilnice, efecte sonore,
    deblocarea progresivă a conținutului, 42 de realizări, inventar cu 78 de
    obiecte și animații RPG.

  \item \textbf{Un modul educațional funcțional} — cu 673 de exerciții matematice reale,
    un mod de examen simulat, randare matematică cu KaTeX şi sistem de progres persistent.

  \item \textbf{Un modul de puzzle-uri de șah tactice} — cu 70 de probleme de tip mat în
    2--4 mutări validate algoritmic și un mecanism de rezolvare pe linia principală.

  \item \textbf{O arhitectură solidă} — bazată pe React Context + useReducer cu
    persistență AsyncStorage, TypeScript strict și navigare tipizată.
\end{enumerate}

Aplicația demonstrează că un singur dezvoltator poate construi, în cadrul unui proiect
de licență, o aplicație mobilă funcțională și complexă care integrează modele de
machine learning \textit{on-device}, fără a depinde de infrastructură cloud.

\section{Limitări curente}

În forma sa actuală, aplicația prezintă câteva limitări asumate, identificate pe parcursul
dezvoltării și testării:
\begin{itemize}
  \item \textbf{Dependența de internet pentru randarea matematică} — biblioteca KaTeX este
    încărcată din CDN, ceea ce face ca modulul de învățare să necesite o conexiune activă
    pentru afișarea corectă a formulelor; restul aplicației funcționează \textit{offline}.
  \item \textbf{Suport audio limitat la Android} — muzica de fundal este redată din resursele
    native Android (\texttt{res/raw}); portarea completă pe iOS necesită includerea
    fișierelor în bundle-ul corespunzător.
  \item \textbf{ELO fix al jucătorului în Maia Chess} — parametrul \texttt{elo\_oppo} este
    fixat la 1600, indiferent de nivelul real al utilizatorului, ceea ce menține constant
    stilul adaptiv al adversarului AI.
  \item \textbf{Acoperirea parțială a testării automate} — validarea s-a bazat preponderent
    pe testare manuală pe dispozitiv fizic și emulator, completată de un test unitar de
    randare și de verificări de integritate în cod.
\end{itemize}
Aceste limitări nu afectează funcționalitatea de bază a aplicației și constituie puncte de
plecare naturale pentru direcțiile viitoare de dezvoltare prezentate în continuare.

\section{Direcții viitoare de dezvoltare}

\subsection{Extinderea conținutului educațional}
Adăugarea de noi discipline (fizică mecanică, chimie organică, informatică) cu seturi
suplimentare de exerciții matematice şi ştiințifice.

\subsection{Repetiție spațiată (spaced repetition)}
Introducerea unui algoritm de repetiție spațiată (de exemplu SM-2 sau sistemul Leitner)
pentru a reprograma automat exercițiile și intrările de jurnal greșite sau dificile la
intervale crescătoare, valorificând câmpul \texttt{lastReviewedAt} deja prezent în model
și maximizând retenția pe termen lung.

\subsection{Rating adaptiv al jucătorului}
Înlocuirea parametrului fix \texttt{elo\_oppo = 1600} cu un rating al jucătorului calculat
adaptiv (de exemplu prin sistemul Glicko-2) pe baza rezultatelor împotriva nivelurilor Maia,
oferind atât o adversitate mai realistă, cât și un indicator de progres suplimentar.

\subsection{Sincronizare cloud opțională}
Implementarea unui backend opțional (Firebase / Supabase) pentru sincronizarea
progresului pe mai multe dispozitive și funcționalitate de leaderboard global.

\subsection{Modul multiplayer pentru șah}
Adăugarea posibilității de a juca șah contra altor utilizatori ai aplicației în timp
real, folosind WebSocket-uri.

\subsection{Îmbunătățirea clasificatorului AI}
Fine-tuning al modelului ResNet pe un set de date mai relevant contextului educațional
(ex. recunoașterea tipurilor de probleme matematice din fotografii de caiete).

\subsection{Notificări push}
Implementarea notificărilor zilnice de reamintire a streak-ului de concentrare și a
exercițiilor de rezolvat.

\subsection{Suport iOS complet}
Testarea și corectarea comportamentului pe dispozitive iOS, cu publicarea în App Store.

\subsection{Accesibilitate}
Adăugarea suportului pentru modul de contrast ridicat și compatibilitate cu cititorii
de ecran (TalkBack / VoiceOver).
